## Purpose & Scope
This patch release updates documentation, packaging metadata, and platform consistency guarantees for `project-xox` without modifying any runtime behavior, Rust bindings, or CORE semantic contracts:

1. **Audited README Description on PyPI:** Package description metadata is updated via `pyproject.toml` (`readme = "README.md"`) so that PyPI renders the latest audited documentation directly from `main`.
2. **Refined Semantic Explanations & Boundaries:**
   - Hero section explicitly highlights rejection of direct boolean coercion with clear `TypeError` demonstration.
   - Clarified that operational events (e.g., `NetworkTimeoutError`) are distinct from epistemic uncertainty (`UNKNOWN`), and that mapping an outage or timeout to `UNKNOWN` is an application-authored policy.
   - Added compact, evidence-disciplined external adversarial evaluation table with explicit qualification distinguishing integration observations from official test suite proofs.
3. **Platform Baseline Consistency:**
   - Corrected binary compatibility baseline documentation in the README to explicitly match released wheel artifact tags: `manylinux2014_x86_64` / `manylinux_2_17_x86_64` (glibc 2.17+).

## CORE Semantic Invariants (Preserved Unaltered)
- **Tri-State Values:** `xox.TRUE`, `xox.FALSE`, `xox.UNKNOWN`.
- **Ingress:** `xox.from_bool()` strictly requiring exact Python `bool`.
- **Truthiness Prohibition:** Direct boolean coercion raises `TypeError`.
- **Strong Kleene ($K_3$) Logic:** `~`, `.lazy_and()`, `.lazy_or()` with strict short-circuiting and exception propagation.
- **Egress:** `.collapse_or()` requiring a zero-argument callable returning exact Python `bool`.
